The Shop Hub Plan

One website that everything links to, hosted free on GitHub, updated by asking. Classroom keeps doing what it is good at.

Your question, answered

You asked whether students could submit logbooks online, then clarified you meant routing them to the right file rather than collecting work on the site. That distinction is the whole plan.

Routing is easy. Collecting is not — and you do not need it.

A GitHub Pages site is static: files served to a browser, no server, no database. It can send a student to a template, an assignment, a video or a rubric in one click. It cannot receive anything back. That sounds like a limitation until you notice that Classroom already does the receiving well — it hands each student their own copy, collects it, timestamps it, and puts the grade in the gradebook.

So: the site is where things are. Classroom is where work goes. No student work, names, or grades ever touch the site or the repository.

How the three pieces fit

The student's path is always the same, whatever the assignment.

Where they start Google Classroom The assignment. One or two lines, a due date, and a link to the site. Attach the template here so each student gets their own copy.
→
Where they read The Shop Hub Instructions, examples, the rubric, safety, the pathway guides. Everything that used to be pasted into a dozen assignments, written once.
→
Where they work Their Drive Their own copy of the template. They fill it in and turn it in through Classroom, exactly as they do now.

The thing you gain is that the middle box has one version. Today, when the logbook expectations change, you edit however many assignments repeated them. After this, you tell me, I edit one page, and every assignment ever written is current — including last year's.

What lives where

The dividing line is whether it is the same for everyone.

On the site
  • The seven pathway guides
  • How the logbook works, with worked examples
  • Classroom rules, grading, uniform, safety
  • The welcome packet and pathway chooser
  • Assignment instructions and rubrics
  • Equipment and software how-tos
  • Links out to templates, videos, Festo, UR Academy
  • A glossary of the terms we actually use
Never on the site
  • Student names, rosters or contact details
  • Student work, submissions or photographs
  • Grades, scores or comments
  • Anything from a student's Drive
  • Recommendation letters or evaluations
  • Budget, purchasing or personnel documents

Worth saying plainly: a GitHub Pages site is public to anyone with the address, and a public repository's history keeps a copy of every file ever committed — deleting a file later does not remove it from history. So the rule is not “take it down if it was a mistake,” it is “it never goes in.” Everything in the left column is material you would hand any student on day one, which is why this works.

Linking to a Drive template so every student gets their own copy

This is the mechanic that makes the routing idea work, and it has one real gotcha.

  1. Open the template and copy its normal URL. It ends in /edit followed by some parameters.
  2. Change the sharing to “anyone with the link — viewer.” The copy link does not work on a file that is not link-shared. This is also the step your district may restrict, so it is on the check-first list below.
  3. Replace everything from /edit onward with /copy. So .../d/1z7mQ4.../edit?usp=sharing becomes .../d/1z7mQ4.../copy.
  4. Put that link on the site. A student clicking it gets a “Make a copy” prompt, and the copy lands in their own Drive, leaving your original untouched.

The gotcha: this trick does not survive being attached inside a Google Classroom assignment — Classroom overrides the link and shares the original instead. That is fine here, because the copy link lives on the site and the student reaches it by clicking through. For work you are going to collect and grade, keep using Classroom's own “make a copy for each student” attachment, which is more reliable and connects to the gradebook.

How updating actually works

This is the part that matters most to you, so it is worth being concrete about who does what.

You say what you want changed
In plain language, here. “The eye protection line should say Makerspace only.” “Add a page for the new resin printer.” “Automation needs a fourth project brief.”
I make the edit and push it
I have the repository on your machine and can commit and push to GitHub directly. GitHub Pages rebuilds on its own; the change is live in about a minute.
Nothing you linked ever breaks
Because the page addresses stay put, an assignment you wrote in October still points at the current version in April. This is the entire benefit over pasting text into assignments.
Everything is recoverable
Git keeps every version. If a change was wrong, going back to Tuesday's version is a request, not a rescue operation. This also fixes the “nothing lives on my machine” problem you raised — the repository is a real backup that exists in two places.
You are never blocked on me
Every page is plain HTML in a folder you can open. GitHub's own web editor will let you fix a typo from a phone if you ever need to.

Check these before we commit to it

All five are quick, and any one of them could change the plan. Worth doing before I build anything real.

Is github.io reachable on student devices? Open one on a student Chromebook on the school network. Some districts filter the whole domain. If it is blocked, the site is useless to students — and a district-hosted page or a Google Site would be the fallback.
Can you link-share outside the domain? Try setting one harmless template to “anyone with the link.” If the admin console forbids it, the copy-link trick is out and templates stay attached in Classroom instead. The site still works; it just links to the assignment rather than the file.
Does the school want to own the repository? A repo under your personal GitHub is yours and leaves with you. One under a school organization outlives you in the role. There is a real trade-off here and it is worth a conversation with whoever would inherit the shop.
Is anyone expecting this to be official? A public page with the school's name on it reads as school communication. Worth telling your principal what it is before a parent finds it, not after.
Accessibility Public school content generally needs to meet accessibility standards. Plain HTML with real headings and good contrast starts in a decent place, but if the district has a stated standard, I should build to it from the start rather than retrofit.

Suggested order

Small enough at each step that stopping after any one of them still leaves you better off.

Phase 1Prove it
  • You create the GitHub account and an empty repository.
  • I put up the home page and the seven pathway guides — already written.
  • Turn on Pages, confirm it loads on a student device.
  • Link one existing Classroom assignment to it and see how it feels.
Phase 2Move the core
  • Welcome, rules, grading, uniform, logbook, pathway chooser — all built already.
  • Add the copy-links to the templates, if link sharing is permitted.
  • Rewrite your recurring Classroom assignments down to a line and a link.
Phase 3Grow it
  • Skill and equipment how-tos, added when you notice you have explained something twice.
  • Assignment pages for the recurring ones.
  • Glossary, so the vocabulary stops drifting.
  • A teacher-only section, if you want the binder there too — it would need a separate private repository.

What I still need from you

The GitHub account name
It becomes part of the address. Something institutional reads better than a personal handle — and it is awkward to change later, since every link you have handed out contains it.
The five checks above
Particularly the first two. Both are five-minute answers and either one could redirect the whole plan.
What the home page should push people toward
My assumption is four doors: New here, The logbook, Pathways, Rules and grading. If a student's most common reason for visiting is something else, that should be a door instead.
Whether the other assignments you mentioned change this
You said you want to do other assignments. If some of them need students to produce something structured rather than fill in a doc, tell me what — there are things a static page can do in the browser without storing anything, and that is worth designing for now rather than bolting on.
